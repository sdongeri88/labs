# Специфікація функцій TaskTracker (СР3, варіант 15)

Документ описує, **що** робить застосунок, а не як. Ідентифікатори сценаріїв (UC-01 … UC-06)
використовують тести, посібник користувача й журнал застосунку.

## 1.1. Межі системи

| Входить | Свідомо не входить |
|---|---|
| облік завдань дошки: створення, призначення виконавця, пошук | облікові записи, паролі й розмежування прав |
| переміщення завдань колонками за таблицею переходів і лімітами WIP | облік витраченого часу й вартості робіт (зроблено в ЛР 1–8, у СР3 не входить) |
| звіт «завантаження виконавців» на поточну дату | графічний інтерфейс, вебдоступ, база даних |
| збереження дошки в одному файлі JSON і завантаження під час запуску | одночасна робота кількох користувачів з одним файлом |
| журнал роботи у файлі `logs/tasktracker.log` | сповіщення поштою чи в месенджери |

## 1.2. Словник домену

| Термін | Ідентифікатор у коді | Значення |
|---|---|---|
| дошка | `ITaskRepository`, `JsonBoardRepository` | усі завдання команди разом із довідником учасників |
| завдання | `BoardTask` | документ зі станом: назва, пріоритет, оцінка, виконавець, колонка, історія |
| колонка | `BoardColumn` | стан завдання: Backlog, Todo, InProgress, Review, Done |
| переміщення | `BoardTask.MoveTo`, `TaskMove` | зміна колонки з записом в історію |
| таблиця переходів | `TransitionTable` | які колонки досяжні з поточної |
| ліміт WIP колонки | `WipLimits.ForColumn` | скільки завдань може одночасно бути в колонці |
| особистий ліміт | `WipLimits.Personal` | скільки активних завдань може мати один виконавець |
| активне завдання | `BoardTask.IsActive` | завдання в колонках InProgress або Review |
| рішення правила | `MoveVerdict` | дозволено або причина відмови |
| учасник, виконавець | `Member`, `BoardTask.AssigneeLogin` | людина з логіном і тижневою місткістю |
| місткість | `Member.WeeklyCapacityHours` | скільки годин на тиждень учасник віддає дошці |
| оцінка | `BoardTask.EstimateHours` | очікувана трудомісткість завдання, годин (decimal) |
| завантаження | `MemberWorkload`, `WorkloadCalculator` | години активних завдань ÷ місткість, % |
| рівень завантаження | `WorkloadLevel` | вільний, нормально, перевантажений |
| пріоритет | `TaskPriority` | Critical, High, Normal, Low (1–4) |

## 1.3. Сценарії використання

Дійова особа в усіх сценаріях — **керівник команди** (працює з консоллю).

### UC-01. Створити завдання (ядро варіанта)

- **Мета:** записати нову роботу на дошку.
- **Передумова:** дошку завантажено.
- **Основний перебіг:**
  1. Керівник вводить назву, пріоритет, оцінку в годинах і (необов'язково) логін виконавця.
  2. Система перевіряє ввід на межі прикладного шару.
  3. Система видає завданню наступний вільний номер.
  4. Система створює завдання в колонці Backlog із датою створення «сьогодні».
  5. Система показує рядок створеного завдання й пише до журналу Information.
- **Альтернативи:**
  - 2а. Назва порожня або довша за 80 символів, пріоритет поза 1–4, оцінка не число чи поза 0–80 —
    система показує пояснення й повторює запит; порожня назва скасовує сценарій.
  - 2б. Виконавця з таким логіном немає в команді — пояснення, завдання не створюється, Warning у журналі.
- **Постумова:** на дошці на одне завдання більше, воно в Backlog.
- **Тести:** `Create_ValidInput_AddsTaskToBacklogWithAssignee`, `Create_UnknownAssignee_FailsAndLogsWarning`,
  `Create_EmptyTitle_FailsWithTitleMessage`.

### UC-02. Перемістити завдання дошкою (ядро варіанта)

- **Мета:** відобразити хід роботи, змінивши колонку завдання.
- **Передумова:** завдання існує.
- **Основний перебіг:**
  1. Керівник вводить номер завдання і назву цільової колонки.
  2. Система перевіряє, що номер — додатне число, а колонка — одна з п'яти.
  3. Система знаходить завдання.
  4. Система застосовує профільне правило (таблиця 1.4): перехід, виконавець, ліміт колонки, особистий ліміт.
  5. Система змінює колонку, дописує історію з поточним часом і пише Information.
- **Альтернативи:**
  - 2а. Номер або колонку введено некоректно — пояснення, стан не змінюється.
  - 3а. Завдання не знайдено — пояснення, стан не змінюється.
  - 4а. Правило відхилило переміщення — виняток `MoveRejectedException` з причиною, повідомлення
    «Відхилено: …», Warning у журналі, стан не змінюється.
- **Постумова:** завдання в новій колонці, в історії на один запис більше.
- **Тести:** `Move_AllowedTransition_MovesAndRecordsFixedTime`, `Move_BadInput_FailsWithoutException`,
  `Move_RuleRejects_ThrowsAndLogsWarning`, `Move_IntoFullReviewOfDemoBoard_RejectedByColumnLimit`,
  `Check_DecisionTableRow_ReturnsVerdict`.

### UC-03. Призначити виконавця

- **Мета:** закріпити завдання за учасником команди.
- **Передумова:** завдання існує і не в колонці Done.
- **Основний перебіг:** 1) керівник вводить номер завдання і логін; 2) система знаходить завдання й учасника;
  3) система призначає виконавця й показує результат.
- **Альтернативи:**
  - 2а. Номер некоректний, завдання або учасника не знайдено, логін порожній — пояснення.
  - 3а. Завдання вже в Done — виняток домену, «Відхилено: …», Warning у журналі.
- **Постумова:** у завдання новий виконавець.
- **Тести:** `Assign_ExistingTaskAndMember_SetsAssignee`, `Assign_UnknownTaskOrEmptyLogin_Fails`,
  `Assign_DoneTask_ThrowsDomainExceptionAndLogsWarning`.

### UC-04. Знайти завдання

- **Мета:** отримати список завдань за критеріями.
- **Основний перебіг:** 1) керівник вводить виконавця, колонку і фрагмент назви (будь-який можна лишити
  порожнім); 2) система відбирає завдання, що задовольняють усі непорожні критерії; 3) показує їх за
  пріоритетом, потім за номером.
- **Альтернативи:** 1а. Невідома назва колонки — пояснення; 2а. нічого не знайдено — «Знайдено: 0».
- **Тести:** `Find_NoMatches_ReturnsEmpty`, `Find_AssigneeAndColumn_ReturnsSingleMatch`,
  `Find_SeveralMatches_SortedByPriorityThenId`, `Find_UnknownColumn_FailsWithMessage`.

### UC-05. Звіт «завантаження виконавців» (обов'язковий звіт варіанта)

- **Мета:** побачити, хто вільний, а хто перевантажений, перш ніж брати нову роботу.
- **Основний перебіг:** 1) керівник обирає звіт; 2) система для кожного учасника рахує активні завдання,
  їхні години й відсоток від місткості (таблиця 2); 3) показує таблицю за спаданням завантаження, потім
  за логіном, і завантаження команди загалом.
- **Альтернативи:** 2а. У команді немає учасників — порожня таблиця й 0 %; 2б. у учасника немає
  активних завдань — 0 % і рівень «вільний».
- **Тести:** `Build_SeveralMembers_SortedByLoadThenLogin`, `Build_NoMembers_ReturnsEmptyReportWithZeroLoad`,
  `Calculate_OnlyActiveTasksOfMember_AreCounted`.

### UC-06. Зберегти дошку

- **Мета:** не втратити зміни між запусками.
- **Основний перебіг:** 1) керівник обирає «зберегти» або «вийти»; 2) система записує дошку у
  `data/board.json`; 3) показує «Дошку збережено.».
- **Альтернативи:** 2а. Файл недоступний для запису — Error із контекстом у журналі, повідомлення
  «Не вдалося зберегти дошку», застосунок продовжує роботу; 0а. під час запуску файлу немає —
  система створює його з умовних даних (8 учасників, 60 завдань).
- **Тести:** `Save_StorageAvailable_SavesOnce`, `Save_StorageFails_LogsErrorAndRethrows`,
  `Open_MissingFile_SeedsDemoBoardAndSavesIt`, `SaveChanges_ThenOpen_RestoresColumnAssigneeAndHistory`.

## 1.4. Правила домену як таблиці рішень

**Таблиця 1. Профільне правило: переміщення завдання.** Ліміти за замовчуванням: Todo — 8, InProgress — 5,
Review — 3, Backlog і Done — без ліміту; особистий ліміт — 2 активні завдання. Перевірки йдуть зверху вниз,
перша невдала визначає рішення. Кожен рядок — один `[InlineData]` тесту `Check_DecisionTableRow_ReturnsVerdict`.

| № | Перехід | Виконавець | Уже в цільовій колонці | Інших активних у виконавця | Рішення |
|---|---|---|---|---|---|
| 1 | Backlog → Todo | — | 7 з 8 | — | Allowed |
| 2 | Backlog → Todo | — | 8 з 8 | — | ColumnLimitReached |
| 3 | Todo → InProgress | немає | 0 | — | AssigneeRequired |
| 4 | Todo → InProgress | є | 4 з 5 | 1 з 2 | Allowed |
| 5 | Todo → InProgress | є | 5 з 5 | 0 | ColumnLimitReached |
| 6 | Todo → InProgress | є | 3 з 5 | 2 з 2 | PersonalLimitReached |
| 7 | InProgress → Review | є | 2 з 3 | 1 | Allowed |
| 8 | InProgress → Review | є | 3 з 3 | 1 | ColumnLimitReached |
| 9 | Review → InProgress (на доопрацювання) | є | 0 | 1 | Allowed (завдання вже активне) |
| 10 | Review → Done | є | 20 | 1 | Allowed (Done без ліміту) |
| 11 | Backlog → Done | є | 0 | 0 | ForbiddenTransition |
| 12 | Done → Todo | є | 0 | 0 | ForbiddenTransition |

**Таблиця 2. Завантаження виконавця.** Завантаження = години активних завдань × 100 ÷ тижнева місткість.

| Умова | Результат |
|---|---|
| місткість ≤ 0 | помилка програміста (`ArgumentOutOfRangeException`), до розрахунку не доходить |
| активних завдань немає | 0 %, «вільний» |
| відсоток < 50 | «вільний» |
| 50 ≤ відсоток ≤ 100 | «нормально» |
| відсоток > 100 | «перевантажений» (верхньої межі немає) |

Округлення: до цілого відсотка, `MidpointRounding.AwayFromZero` (102,5 → 103). Години — `decimal`,
від'ємна оцінка відхиляється на вході; оцінка понад 80 год для одного завдання відхиляється як
некоректний ввід. Звіт для команди без учасників — 0 %.

## 1.5. Життєвий цикл документа

Рядки — поточний стан, колонки — подія «перемістити до …».

| Стан \ Подія | → Backlog | → Todo | → InProgress | → Review | → Done |
|---|---|---|---|---|---|
| Backlog | — | Todo | заборонено | заборонено | заборонено |
| Todo | Backlog | — | InProgress | заборонено | заборонено |
| InProgress | заборонено | Todo | — | Review | заборонено |
| Review | заборонено | заборонено | InProgress | — | Done |
| Done | заборонено | заборонено | заборонено | заборонено | — |

Done — кінцевий стан: з нього немає переходів, виконавця не змінюють.
