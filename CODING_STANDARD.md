# Стандарт кодування проєкту TaskTracker

Версія 1.0 — ЛР № 1. Автор: Костянтин Решетнік.

## 1. Загальні положення

1.1. Стандарт обов’язковий для всього коду рішення `TaskTracker` (проєкти `TaskTracker.Core` і `TaskTracker.App`).

1.2. Мова коду — C# (остання версія, `LangVersion = latest`), цільова платформа — `net8.0`.

1.3. Ідентифікатори пишемо англійською; коментарі, XML-документацію й повідомлення комітів — українською.

1.4. Складання має завершуватися з **0 попереджень** (`dotnet build`). Код із попередженнями в гілку `main` не потрапляє.

1.5. Кожне вимкнення правила аналізатора супроводжується коментарем-обґрунтуванням у `.editorconfig`. Точкове придушення через `[SuppressMessage]` — не більше двох на весь проєкт, з обов’язковим `Justification`.

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
|---|---|---|---|
| Клас, запис | PascalCase, іменник | `WorkLog` | `worklog` |
| Інтерфейс | `I` + PascalCase | `IWorkTaskRepository` | `Repository` |
| Метод | PascalCase, дієслово | `TotalHours`, `AddLog` | `calc` |
| Властивість | PascalCase, іменник | `HourlyRate` | `GetHourlyRate` |
| Приватне поле | `_` + camelCase | `_logs` | `m_Logs` |
| Локальна змінна, параметр | camelCase | `totalCost` | `tc` |
| Константа | PascalCase | `MaxLogCount` | `MAX_LOGS` |
| Перелічення | PascalCase, однина | `WorkTaskStatus` | `WorkTaskStatuses` |
| Простір імен | `TaskTracker.<Проєкт>.<Тека>` | `TaskTracker.Core.Domain` | `Domain` |

2.1. Скорочення в іменах заборонені, крім загальноприйнятих (`Id`, `Url`, `Http`).

2.2. Булеві властивості починаються з `Is`, `Has` або `Can`: `IsLead`.

2.3. Імена типів не повинні збігатися з типами .NET, що підключені неявно (`Task`, `TaskStatus`), тому документ називається `WorkTask`, а його стан — `WorkTaskStatus`.

2.4. Ім’я файлу збігається з ім’ям єдиного публічного типу в ньому (`WorkTask.cs` → `WorkTask`).

## 3. Форматування

3.1. Відступ — 4 пробіли; табуляція заборонена. Для `.csproj`, `.props`, `.json` — 2 пробіли.

3.2. Довжина рядка — не більше ніж 100 символів.

3.3. Фігурні дужки — стиль Allman (кожна дужка на окремому рядку); дужки обов’язкові навіть для однієї інструкції в тілі `if`, `for`, `foreach`, `while`.

3.4. Між членами класу — рівно один порожній рядок; два порожні рядки поспіль заборонені.

3.5. Директиви `using` — на початку файлу, поза простором імен, `System.*` першими; невживані видаляються.

3.6. Простір імен — файлового рівня: `namespace TaskTracker.Core.Domain;`.

3.7. Кодування файлів — UTF-8, у кінці файлу один символ нового рядка, пробіли в кінці рядків заборонені.

3.8. Порядок членів класу: поля → властивості → методи; у межах групи — спочатку `public`, потім `private`.

3.9. Для вбудованих типів пишемо явний тип (`decimal sum = 0m;`), а не `var`.

## 4. Коментарі та документація

4.1. Коментар пояснює **чому** ухвалено рішення, а не **що** робить рядок коду.

```csharp
// погано: коментар переказує код
// додаємо години до суми
sum += log.Hours;

// добре: коментар пояснює причину рішення
// замовник оплачує лише перевірені години, тому чернетки не враховуємо
if (log.IsApproved)
{
    sum += log.Hours;
}
```

4.2. Кожен публічний тип бібліотеки `TaskTracker.Core` має XML-коментар `<summary>` з одного речення.

4.3. Публічні методи з нетривіальною логікою мають `<summary>`; з ЛР № 4 обов’язкові також `<param>` і `<returns>`.

4.4. Закоментований код у репозиторій не потрапляє — для цього є історія Git.

4.5. Позначка `TODO` дозволена лише з номером ЛР, у якій її буде закрито: `// TODO(ЛР4): ...`.

## 5. Структура проєкту

5.1. `TaskTracker.Core` — бібліотека з логікою предметної області; не містить `Console` і будь-якого введення-виведення.

5.2. `TaskTracker.App` — тонкий консольний шар: створює об’єкти, викликає методи `Core`, друкує результат.

5.3. Сутності предметної області лежать у теці `TaskTracker.Core/Domain`, простір імен `TaskTracker.Core.Domain`.

5.4. Один файл — один публічний тип.

5.5. Спільні параметри складання задаються лише в `Directory.Build.props`, а не дублюються в `.csproj`.

## 6. Правила комітів

6.1. Повідомлення — за Conventional Commits: `тип: коротка суть` у наказовому/доконаному способі, українською, до 72 символів.

6.2. Дозволені типи: `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`.

6.3. Один коміт — одна завершена зміна; після кожного коміту проєкт збирається без попереджень.

6.4. Теки `bin/`, `obj/`, файли `*.user` до репозиторію не потрапляють (`.gitignore`).

6.5. Наприкінці кожної ЛР ставиться мітка `labN`.
